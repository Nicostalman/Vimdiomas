## Decisions

Settled with the dev during this sprint-start conversation, on 2026-09-09.

| Decision | Rationale |
| --- | --- |
| The merged tree is **flat**: `tree-Chinese/Vocabulary/Food.md` and `Food.pdf` sit side by side, no `md/`/`pdf/` subfolders | The backlog raised the subfolder split and doubted it in the same breath. No performance concern at this scale — a notebook is dozens of files and the app already walks it with `rglob`. Inspect Tree's PDF/MD modes filter by extension anyway, so the physical split buys nothing the UI can't do for free, while costing an extra path level every module has to know about and hide from the user. |
| Git treatment is **untrack-only**: `git rm --cached` plus a `.gitignore` entry. Already-pushed history is **not** rewritten | Dev's choice against the recommendation to purge history with `git-filter-repo`. Consequence on record: the two currently tracked source files remain retrievable from the remote's history indefinitely. See Assumptions. |
| The trees' **testing question is settled — no test reads the real trees** | Checked during this conversation: every test in `tests/` builds its fixture trees under pytest's `tmp_path`. Untracking `source/`/`notebook/` breaks nothing. This is the question Sprint 2 blocked #6 on, and it is now answered. |
| `tree-Chinese/` lives at the **project root**, where `source/` and `notebook/` do now | The real question — a program folder outside the source code, one folder per language — is installation-wizard territory, and the backlog says the wizard is not touched this sprint. Keeping the location fixed keeps M1 a pure merge. |
| Git untracking is **folded into M1**, not a milestone of its own | M1 already moves every file in both trees, so the `.gitignore` entry lands in the same commit as the move. Splitting it would mean `tree-Chinese/` gets committed in one milestone and untracked in the next, putting the private content into history one more time before it is removed. |
| The shared tree widget is **its own milestone (M3), before Inspect Tree** | Dev's choice. Extract the shared base from `EntryTree` first and prove the entry screen is visually identical, then build Inspect Tree on top of it — rather than growing the abstraction inside the milestone that also introduces new behaviour. Serves the backlog's wish to change every tree's layout from one place. |
| The landing menu's **Settings submenu is entirely dummy items** | Matches the backlog ("Implementation is not expected outright, leave dummy items"). Language registration and input-method configuration belong to the installation wizard, which owns the data these settings would write. |
| The LaTeX/PDF format rework is **the last milestone (M6)** | It touches only `compile.py` and `templates/xecjk.tex`, so it blocks nothing and nothing blocks it. Parked at the end where its interview can happen without holding up the menu and tree work. |
| **Nothing carries over** from Sprint 2's deferred list or Sprint 1's | Dev's explicit instruction: the backlog is the only source of scope for this sprint. Entry screen real estate (Sprint 2 `#22`) is reported by the dev as already handled. |
| **M1 done.** `.idiomas.toml` migration is **silent** (no re-prompt); the merge **moves** `.md` files and **recompiles** `.pdf`s fresh rather than moving the old ones | Settled with the dev during M1's spec interview (2026-09-09). Recorded in `features/M1-2026-09-09-one-tree-per-language/requirements.md`. Implemented, tested, dev-validated against the real notebook. |
| **M2 done.** Language list is a **hardcoded constant** (`LANGUAGES` in `landing.py`), not read from `Config`; the notebook menu's **"Quit" item is removed outright** now that `q` returns to the landing menu; the landing menu, notebook menu, and Settings submenu share their look through a new **`MenuScreen` base** (`base.py`) and `.menu-screen` CSS class | Settled with the dev during M2's spec interview and, for `MenuScreen`, raised by the dev after manual testing (2026-09-09) — the new screens hadn't picked up the notebook menu's centered/bordered look because `app.tcss` targeted `MainMenuScreen` by name. Recorded in `features/M2-2026-09-09-landing-menu/requirements.md`. Implemented, tested, dev-validated. |

| M1's "visual trees don't change" guarantee is **not** promoted to a standing `design.md` convention | Proposed and then reverted at the dev's request during M2 (2026-09-09) — asked for, then explicitly walked back with "go back the tree change". It stays scoped to M1's own `requirements.md`/`plan.md` rather than becoming a cross-milestone rule. |

Recorded in `features/M4-2026-09-09-inspect-tree-functional/requirements.md`. Implemented, tested (full suite 251 passed), dev-validated. |

Recorded in `features/M5-2026-09-09-editing-the-tree/requirements.md`. Implemented, tested (full suite 276 passed), dev-validated. |
| **M6 done — sprint's last milestone.** The vocabulary list is now **raw LaTeX emitted directly** by `compile.py` (a `longtable` with plain `l` columns, passed through pandoc via the `raw_attribute` extension) instead of a pandoc-interpreted markdown pipe table — needed for exact control over alignment/rules/header that pandoc's own conversion couldn't reliably give. The list is **left-aligned and tight to content** (`longtable` centers itself by default via `\LTleft`/`\LTright`, fixed in the template); the header row and table rules are **invisible** while the table structure itself remains; the document font is **12pt**; row spacing is `\arraystretch{1.6}` and columns have a 2em gap (both added after dev feedback on the first compile); the CJK font moved from `Songti SC` to **`Heiti SC`** (`Hiragino Sans GB` was tried first for a "Claude-like," less-serif look but rejected — it corrupts the PDF's `ToUnicode` CMap, breaking copy/paste and text search, caught by the existing `pypdf` integration test) | Settled with the dev during M6's spec interview (2026-09-10) and refined after two rounds of manual testing against the dev's real notebook (2026-09-10). Recorded in `features/M6-2026-09-10-pdf-format-rework/requirements.md`. Implemented, tested (full suite 277 passed), dev-validated by eye against real content (`Asking for directions.pdf`). Merged via PR #23. |

## Assumptions

Taken as given by this sprint; not verified in code or stated in the roadmap.

| Assumption | Origin | Notes |
| --- | --- | --- |
| The dev accepts that untrack-only leaves the two tracked `source/*.md` files in the remote's history permanently | Sprint-start conversation | The backlog says "purge what's already pushed"; the dev chose the narrower option when the trade-off was put to them. If they change their mind, a history rewrite is still possible later — but only gets more expensive. |
| Only Chinese is functional; German is an inert landing-menu entry with no plumbing behind it | backlog · *Landing menu* | Carried unchanged from Sprint 2. The landing menu is built to hold N languages but is fed a hardcoded two. |
| Directories in the tree are exactly one level deep and stay that way | backlog · *further functionality* | "Directories can not be nested." The current trees (`Grammar/`, `Vocabulary/`) already obey this. M5's `n` enforces it; nothing enforces it against a directory the user creates by hand in the filesystem. |
| `.idiomas.toml` files written before M1 (holding `source_root`/`notebook_root`) exist only on the dev's machine | Sprint-start conversation | The config file is gitignored, so the only live instance is the dev's. Settled in M1: migration is silent (see Decisions). |
