# M1 · Navigation conventions — validation

Grounded in the roadmap's **Done when**: "Every screen can be driven end to
end with `hjkl`, `enter` and `q` alone; `q` on the main menu exits; `q` inside
a text field types a `q`; no `escape` binding remains in the codebase; and
`stack.md` carries the key map."

## Automated

- `pytest` passes in full, including `tests/test_tui_entry_screen.py` amended
  for the removed `right`→`select_cursor` binding (any test asserting that
  behavior needs updating or removing).

## Manual, by screen

**Main menu**
- [ ] `j`/`k` move the option highlight up/down; arrow keys still work too.
- [ ] `enter` activates the highlighted option.
- [ ] `q` exits the app (only screen on the stack).

**Entry screen**
- [ ] `j`/`k` move the tree cursor; plain `h`/`l` do nothing (matching the
      arrow keys, which Tree leaves unbound for plain left/right).
- [ ] `enter` on a valid target (category / uncategorized / new category)
      focuses the form, matching current `NodeSelected` behavior.
- [ ] `L` (or `shift+→`) from the tree (not from inside a field) focuses the
      first form field.
- [ ] `shift+←` from inside any form field focuses the tree back. Plain `H`
      typed into a field types the letter H instead — this is expected (see
      *Implementation findings* in `requirements.md`).
- [ ] `q` while the tree has focus pops back to the main menu.
- [ ] `q` while an `Input` has focus **types the letter q** into the field
      instead of navigating away.
- [ ] `Tab` still cycles fields as before (untouched by this milestone).
- [ ] Footer hint no longer mentions `Esc`.

**Browse screen**
- [ ] On opening Browse, focus starts on `#results` (not a filter `Input`),
      so `q` works immediately without switching panels first.
- [ ] `j`/`k` move the results list highlight when it has focus.
- [ ] `L` from the results list (not from inside a filter) cycles forward:
      results → filename-filter (wraparound).
- [ ] `shift+→`/`shift+←` cycle filename-filter → tag-filter → results →
      filename-filter (wraparound in both directions), including when
      starting from inside a filter `Input`.
- [ ] `q` from any of the three panels pops back to the main menu.
- [ ] `q` while a filter `Input` has focus types the letter q.

**Placeholder screen** (Compile / Notebook / Inspect tree results)
- [ ] `q` pops back to the main menu. `escape` does nothing (no longer bound).

## Regression check

- [ ] Creating an entry (hanzi + optional fields → Create) still works
      end-to-end via keyboard only, using the new key map, with no mouse.
- [ ] No behavior from M2–M4 is implemented or assumed here — e.g. `q` from
      the entry screen does **not** trigger a compile (explicitly deferred to
      M3; confirm no PDF is regenerated by watching `notebook_root` mtimes,
      or absence of a `_compile`/`compile_all` call in the `q` path).
