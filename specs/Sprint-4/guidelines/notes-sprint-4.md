Agent-maintained companion to [`backlog.md`](backlog.md), which is written by the
dev and is the authoritative statement of intent. This file does not restate it;
it records what was decided, assumed, or postponed while the backlog was turned
into [`../roadmap-sprint-4.md`](../roadmap-sprint-4.md), and it grows as the
sprint runs.

dev's own `postponedfeatures.md` marks exactly the four backlog sections with
`(4)` — *Instalation wizard*, *Classes rework*, *Enter vocabulary fixes*,

## Decisions

Settled with the dev during this sprint-start conversation, on 2026-09-12.

| Decision | Rationale |
| --- | --- |
| **One tree per language stands.** Two languages = two trees, `.md` and `.pdf` side by side in each | The backlog's wizard item 4 says "two languages are equal to 4 trees, 2 md and 2 pdf", which contradicts Sprint 3 M1's flat merge. Put to the dev; they confirmed M1 holds and the backlog line was written from the pre-M1 model. |
| **The wizard is built from Textual screens**, not `input()` prompts before the TUI | Dev's choice. Consequence: the classes rework (M1, M2) is ordered **before** the wizard (M5, M6), so the wizard's screens are built on the new panel/field classes rather than reworked afterwards. |
| **Multi-language is config-driven, German stays inert** | Dev's choice against building a working German notebook. The wizard stores the registered languages and the landing menu reads them from config instead of `landing.py`'s hardcoded `LANGUAGES`, but only Chinese opens a real notebook. |
| **Config leaves the repo:** `~/.config/idiomas/config.toml`. **Trees go where the user chooses**, defaulting under `~/Documents/Idiomas/` | Dev's own point: the user never sees where the code lives, so nothing user-owned should depend on it. Verified in code: `__main__.py`'s `PROJECT_ROOT` and `compile.py`'s `TEMPLATE_PATH` both resolve `__file__.parent.parent.parent` back to the repo, which breaks once the package is installed (the config would land in site-packages; `templates/` is outside `src/` and wouldn't ship). This also answers Sprint 3's postponed item on moving the trees out of the source directory. |
| **No migration of the dev's existing setup.** The old repo-root `.idiomas.toml` is ignored; the dev runs the wizard fresh and points it at their tree | Dev's choice against a pre-filled wizard and against a silent migration (contrast Sprint 3 M1, which migrated silently). Moving `tree-Chinese/` out of the repo is the dev's manual step. |
| **Dependency check: block on required, warn on optional.** Required: pandoc, xelatex, xeCJK, the CJK font. Optional: `macism`, `nvim` | Dev's choice. Required tools break the core (compiling); optional ones only degrade one feature each (input switching, Inspect Tree's MD mode). The wizard doesn't install anything. |
| **"PATH" means a console-script entry point.** `idiomas` becomes a real command via `[project.scripts]` | Verified: `pyproject.toml` has no scripts entry and `which idiomas` finds nothing. Brew packaging stays out of scope, as the backlog says. |
| **The wizard's input-method answers are wired into `input_method.py`**, replacing Sprint 2's hardcoded Pinyin Simplified / English International pair | Dev's choice. Otherwise the wizard asks a question nothing reads. German's answers are stored but unused while German is inert. |
| **Panel movement is spatial, and fields must `esc` out first.** H/J/K/L and shift-arrows move left/right/down/up between panels, following the real layout, with no wraparound. They work only when a panel or the backpanel itself has focus — never on content, where shift-arrows are fully inert too (M1 settled this: they mimic the letter keys exactly, giving up `Tree`'s and `Input`'s own shift-arrow defaults). | Dev's choice, following the backlog ("shift+jkhl to work only when focusing the panels"). Replaces `PanelAwareInput`'s current shift+left/right escape hatch and Browse's cyclic `PANEL_IDS` order, so `design.md`'s key table is rewritten in M1. The shift-arrows-on-content nuance was only settled during M1's hands-on testing — the sprint-start conversation hadn't anticipated it. |
| **`tab` on a panel focuses its content, same as `enter`.** General on `Panel`, not a per-screen special case | M1 hands-on feedback: the form panel's tab-focuses-first-field was found to be a hardcoded `EntryScreen` special case, not something every panel got; generalizing it fixed the tree panel too. |
| **The backpanel has its own bordered look (dim/accent, like every panel) and H/J/K/L + shift-arrows to jump to the edge-most panel** | M1 hands-on feedback: `enter` already reached the first panel from the backpanel; not being able to reach the last one, or move vertically, felt like a gap once the border made the backpanel a place worth being in. |
| **The classes rework is two milestones:** build the classes and prove them on Entry (M1), then move every other screen over (M2) | Same approach as Sprint 3's M3→M4: settle the abstraction on the reference screen the backlog itself points to before spreading it. The Browse fixes are validated in M2, as the backlog anticipates ("Hopefully this gets fixed with the classes rework"). |

| **The backpanel is only reachable via `esc` with more than one panel.** Zero panels (a menu) or exactly one (Browse, Inspect Tree) stop `esc` one level short instead | M2 hands-on feedback, generalizing what was first a menu-only rule: with one panel there's exactly as little reason to climb to the backpanel as with none. Only Entry (two panels) still reaches it. `Backpanel.reachable()` (`len(panels()) > 1`) is the single check both `Panel.action_defocus` and `Backpanel.action_defocus` use. |
| **Flat menus get gray padding on all sides of the list**, not just top/bottom | M2 hands-on feedback: left/right padding was needed too, for the same reason vertical padding was — the list's gray background shouldn't touch the screen edge cleanly. |
| **Empty categories render as a bare heading in the PDF**, not left out | M3 spec conversation. A category the dev just created should be visibly present in the notebook, ready to be filled in, rather than silently absent until it has an entry. `compile.py`'s category loop now guards `_render_table` the same way `deck.uncategorized` already was. |
| **`(new category)`'s fields are hidden, not disabled**, and Create is a full no-op on an empty/whitespace name (no more falling back to uncategorized) | M3, following the backlog literally: "only have the text field for the name... not the other 4" and "not... allowed to be left empty." |
